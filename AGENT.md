# AGENT.md

Guidance for AI coding agents (and people) working in this repository.

## What this repository is

`maxio-apiroute` publishes a Python client for Maxio Advanced Billing (formerly Chargify). [apiroute](https://github.com/dougyouch/apiroute) **generates** the client from the OpenAPI 3.1 spec that Maxio's developer portal exports (`developers.maxio.com/static/exports/maxio-advanced-billing-openapi31json.json`). Methods keep the spec's operation names, as Maxio's own SDKs do. The weekly Build workflow keeps the client current, and it's released to PyPI as `maxio-apiroute`.

## Layout

| Path | What it is | Edit by hand? |
| --- | --- | --- |
| `apis.yaml` | The API: spec URL, docs URL, module, client class, auth base class, pagination rules | **yes**: this is the source of truth |
| `specs/advanced_billing.json` | The committed copy of the spec, written by `scripts/generate.py --fetch` | no (fetch it) |
| `specs/advanced_billing.pagination.yaml` | Which list operations get `_all` methods, and how they page | yes |
| `scripts/generate.py` | Fetches the spec, writes `spec_info.py`, runs `apiroute generate`, writes the README table | yes |
| `scripts/next_release.py` | Each release's version, notes and CHANGELOG.md entry, from the commits since the last tag | yes |
| `src/maxio_apiroute/auth.py` | `MaxioAuth`: Basic auth with the API key, the site's host by region, 429 retries, the events host | **yes** |
| `src/maxio_apiroute/__init__.py` | Package docstring | yes |
| `src/maxio_apiroute/spec_info.py` | The operations served from another host (event ingestion), written by `generate.py` | never |
| `src/maxio_apiroute/advanced_billing/` | The generated client (every file starts with `# Generated by apiroute`) | **never** |
| `tests/` | Config checks, auth, pagination; `tests/live/` against a Maxio test site | yes |
| `.github/workflows/` | `ci.yml`, `build.yml` (regenerate, live-test and commit), `release.yml` (every push to main: tag, PyPI, GitHub release) | yes |
| `.agent/skills/apiroute-client.md` | Skill for creating and maintaining repos like this one | yes |

## Rules

- **Never edit generated code.** CI regenerates from `specs/` and fails on any difference. To change generated output:
  - Edit `apis.yaml`, `auth.py` or the pagination rules, and regenerate.
  - If the generator itself is wrong, fix apiroute; the Build workflow picks up its next release.
- **Regenerate after any change** to `apis.yaml`, the pagination rules or the scripts: `uv run python scripts/generate.py`. Add `--fetch` to download the latest spec first. Commit the specs and the generated code together.
- **Live tests use a test site only.** They read `MAXIO_API_KEY`, `MAXIO_SITE` and optionally `MAXIO_REGION`, and refuse a site whose `test` flag isn't set. Never print a key or write one to a file. Clean up what a test creates.
- **Every merge to main is a release.** There's no release PR; `release.yml` tests, tags and publishes each push to main, Build's commits included.
- **Use conventional commits.** The version comes from the commits since the last tag:
  - `feat!:` (or a `BREAKING CHANGE:` footer) is a major release
  - `feat:` is a minor release
  - anything else (`fix:`, `docs:`, `chore:` ...) is a patch
- **The version lives in the git tag**, not `pyproject.toml` (hatch-vcs). Never tag by hand; the release workflow does.
- **Don't edit CHANGELOG.md by hand;** the release commits write it.
- **Before committing:** `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest`. After regenerating, also run the live tests if you have a test site: `MAXIO_API_KEY=... MAXIO_SITE=... uv run pytest tests/live`.

## Common tasks

- **A new list operation has no `_all` method:** its response's list key has no rule yet. Add one to `specs/advanced_billing.pagination.yaml` and regenerate; the generator prints each rule's match count.
- **A spec change broke generation:** the Build workflow fails before committing anything. Reproduce with `scripts/generate.py --fetch`, then fix apiroute, the pagination rules or `auth.py`. Patching `specs/` by hand would be overwritten by the next fetch.
- **A live test fails after a spec update:** the spec and Maxio's responses disagree, or a typed model is wrong. Check the failing response. Fix apiroute if the generator is at fault. Set `nullable_fields: true` in `apis.yaml` if the spec says a field is never null when Maxio sends null, or `open_enums: true` if Maxio sends enum values the spec doesn't list.
- **Release:** nothing to do. Every push to main, and every Build commit, is tested, released and published.
